# Truman World 的连续视频实现

调查日期：2026-09-20。只检查公开网页、浏览器下发的脚本和公开只读状态；没有进入运营者后台或启动对方的付费会话。

## 结论

这个网站将**世界状态、视频生成、直播分发**分开。公开前端接入的主默认路径是 fal 的 `minimax/h3-max/director`，走 WMA / WebRTC 实时视频；还实现了短片续接与其他供应商适配。发现接入代码不代表知道生产环境当时选择了哪个供应商。

本次读取 `/api/broadcast/status` 返回 `configured: true`、`headlessMode: true`、`live: false`、`operator: false`。供应商配置接口需要运营者权限，所以不能确认当前生产配置，也没有观察到正在运行的视频流。后台世界模型、持久化数据库和真实计费情况均未核实。

## 从公开前端确认的机制

1. **世界先运行。** `/api/world/overview` 提供规范场景与世界状态。角色和事件文字流在视频停播时仍有独立展示路径；前端也明确区分世界事件与已验证的视频帧。
2. **实时导演会话。** fal 客户端通过服务端代理打开 `minimax/h3-max/director`，接收音视频轨道。先发 configure，随后发送递增版本的 prompt；生成端回报 pending、applied 和 chunk 等事件，用来追踪画面实际采用了哪个方向。
3. **有会话接续实现。** 前端包含提前启动下一会话、提取当前画面作为开场参考、确认新轨道已产出帧后替换媒体的逻辑。该逻辑受运行时开关及准备条件控制，不能据此认定线上一定启用。
4. **共享直播。** 运营者发布一条媒体流，观众通过 subscribe / answer / heartbeat 加入。状态中的 headlessMode 表明配置了无人值守发布模式；服务器进程形态未知。观众端不是每人单独打开一个视频生成模型。
5. **短片备用路径。** `fal_turbo` 适配器调用站内 `turbo-clip` 接口，给下一段指定约 5 秒的场景方向。从上一成片接近末尾的位置抽帧作图像参考，当前片段开始解码播放后即生成下一段。画面绘到 canvas 后转为媒体流。若生成慢于播放，会等待；代码并不能保证永无停顿。该路径还设置了会话上限与失败后停止自动付费重试。

## “无限”意味着什么

它是持续维护生成会话、持续输入场景方向、处理会话更换，再持续分发输出。不是一个无限时长的 MP4。世界状态负责故事一致性，视频模型负责视觉；二者需要确认与版本记录，不能把文字事件直接当作已显示画面。

fal 官方说明，Director 可在同一连接中持续接收视频并接受新的文字方向，模型保留上下文来衔接生成段。该 API 当前仍标为实验性 alpha，支持的配置及会话规则应以官方文档为准。

## 蝇境适合怎么改

```text
连续果蝇神经模拟 → 规范世界状态 → 节制发送场景方向
                                       ↓
                              H3 Max Director 会话
                                       ↓
                              一路共享直播 → 观众
```

优先验证 Director 的短时流式样片，而不是将大量独立 Sora 任务当作实时直播。保留现有模拟作为行为来源，让光照、位置、转向等进入方向描述；视频生成端不得反向捏造神经测量值。

生产版还需要：服务端 FAL_KEY 与运营者认证、一个常驻发布进程、世界状态和恢复检查点、媒体分发、单会话/每日费用上限、停机与重连策略。Vercel 网页承载观看与控制界面，长期发布进程需要单独部署。此次仅完成研究和网站去棋盘化，没有配置 fal 密钥，也未开启任何付费任务。
